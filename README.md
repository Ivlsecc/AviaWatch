# AviaWatch

Мониторинг цен на авиабилеты: собирает цены с разных сайтов и Telegram-каналов, показывает их в Telegram-боте ([@avia_watcher_bot](https://t.me/avia_watcher_bot)), следит за подписками и даёт владельцу веб-админку с мониторингом и конфигуратором источников.

Главная идея — искать **выгоднее агрегаторов**: опрашивать сразу несколько сайтов, чартеры из Telegram (их нет на Aviasales), составные маршруты через хабы и соседние даты.

## Что умеет

**Бот**
- Поиск по нескольким городам вылета и прилёта сразу («Хургада или Шарм → Москва»), даты или диапазон, пассажиры.
- Выдача: средняя цена по маршруту (±30 дней от сегодня), динамика цены, рекомендация «покупать или ждать» с причинами, топ-5 с пагинацией, ссылки на все сайты, где нашёлся рейс.
- Прогресс поиска: «опрошено 3 из 7 источников».
- 💡 Подсказка гибких дат: «вылет 22.11 дешевле на 4 000 ₽» + кнопка «искать на эту дату».
- 🧩 Составные маршруты (опционально, в фильтрах): два отдельных билета через Стамбул/Анталью/Каир/Дубай…, если выходит дешевле на 7%+.
- Фильтр «мусора»: число пересадок, время в пути, длина стыковки, смена аэропорта, раздельные билеты, ночные стыковки.
- Подписки: порог цены, новый минимум / падение на X%, сводка раз в N часов, тихие часы, пауза. Проверка раз в час (меняется в админке).

**Веб-админка** (`http://localhost:8000`)
- Дашборд: пользователи (DAU/WAU), подписки, поиски, запросы и ошибки источников по часам, задержки, нагрузка CPU/память/диск/сеть.
- Конфигуратор (доска на React Flow): источники с цветом статуса, пулы прокси (провести связь «источник → прокси»), пайплайн обработки; панель настроек источника, «Тест» с живым запросом, сброс автоотключения. Изменения применяются без перезапуска.
- Пользователи: поиск, подписки, история поисков и уведомлений, блокировка, лимиты.
- Бот: режим техработ, свои тексты приветствия/справки, интервал проверки, умолчания для новых; рассылка.
- Логи: ошибки источников, последние поиски.

## Источники

| Источник | Статус | Как устроен |
|---|---|---|
| `kupibilet` — Купибилет | ✅ | Открытый JSON `api-rs-lb.kupibilet.ru/frontend_search`: ≈400 вариантов за 2–3 с, сегменты, багаж, чартеры, `virtual_connection` → самостоятельная пересадка. Часто дешевле всех |
| `tutu` — Туту | ✅ | `offers-api.tutu.ru/avia/offers/v2` + календарь + подсказки городов. Полные маршруты, багаж, раздельные билеты. ≈10 с на день |
| `aviakassa` — Авиакасса | ✅ | `aviakassa.com/api/v4/avia/search/get-recommendations`. Ходит напрямую (`proxy=direct`): через VPN пользователя TLS не проходит. Unix-время у них сдвинуто для Египта — берём местное время строкой |
| `onetwotrip` — OneTwoTrip | ✅ | `/_api/searching/startSync2/`. Местное время → пояс из справочника аэропортов. Мусорные тарифы (≈1 млн ₽) отсекаются. По Египту выдача бедная |
| `aviasales_api` — Aviasales (Travelpayouts Data API) | ✅ | Официальный кэш цен: одна минимальная цена на день. Используется как календарь для средней, тренда и гибких дат |
| `egyptticket` — чартеры Egypt-Ticket | ✅ | Публичный Telegram-канал [t.me/egyptticket](https://t.me/s/egyptticket): места в чартерных блоках «только перелёт», бронь через продавца. Время вылета не указано |
| `ticket_egypt` — горящие чартеры | ✅ | Публичный канал [t.me/ticket_egypt](https://t.me/s/ticket_egypt): самые дешёвые чартеры из выдачи Aviasales (от 4–7 тыс. ₽), цена держится часы |
| `anex` — ANEX Tour, чартеры | ✅ | Открытый JSON `api.anextour.ru/Ticket/` (Sources → Targets → Checkins → Prices): остатки мест на чартерах туроператора «только перелёт», багаж включён. Из Египта — на ближайшие 2–4 дня. Тот же рейс бывает дешевле, чем у агрегаторов |
| Aviasales, живой поиск | ⏳ | Сайт закрыт AWS WAF и детектит любую автоматизацию (Playwright headless и headed — 403). Обход защиты не делаем. Легальный путь — Travelpayouts Flight Search API: токен и маркер подходят, но API отвечает 403 — нужен запрос доступа в кабинете |
| Т-Путешествия | ❌ | Сертификат «Russian Trusted Root CA» (Минцифры) — не устанавливаем |
| Яндекс Путешествия | ❌ | SmartCaptcha — капчи не обходим |
| Аэрофлот, Pegasus, Air Cairo, Azur Air, Kiwi, Ozon Travel, Biletix, Travelata | ❌ | Антибот-защита (JS-challenge / Akamai / Cloudflare / Qrator / Servicepipe) |
| Nordwind, Ural Airlines, ЮТэйр, Победа, EgyptAir, Red Wings, AJet, flydubai, Fun&Sun, Pegas | ❌ | Проверены в октябре 2026: challenge при поиске, SmartCaptcha, Qrator, Cloudflare, DDoS-Guard (Red Wings молча отдаёт пустую выдачу не-браузерам), обрыв соединения |
| Nesma (сайт авиакомпании) | ⏸ | Открыт (Hitit Crane), но цена «from» в USD без части сборов — была бы занижена; тот же рейс есть на Туту |
| Туроператоры: Coral, Sunmar | ⏸ | Раздел «Авиабилеты» — обычный поиск по всем авиакомпаниям (как у агрегаторов), не чартерные блоки; запросы собираются динамически — отложено |
| Библио-Глобус | ❌ | На запрос не из браузера отвечает «Wrong request detected. For API please contact support» — нужен договор об API |
| Clickavia | ⏸ | Открыт, но поиск идёт через веб-сокет Phoenix LiveView, а не обычный запрос; к тому же это общий агрегатор, не чартерный. Отложено |
| City.Travel | ❌ | `POST /avia/load` отвечает, но страница результатов даёт 500, а после серии запросов сайт отдаёт 403 — не трогаем |
| TEZ Tour | — | Только справочник рейсов, билеты отдельно не продаёт |
| Anywayanyday | ⏸ | На техработах |

Одинаковые рейсы с разных сайтов склеиваются в одну строку: цена и ссылка — от самого дешёвого, подробности маршрута — от самого подробного, остальные сайты — дополнительными ссылками.

## Быстрый старт (Windows, без Docker)

```bash
cp .env.example .env          # BOT_TOKEN, ADMIN_TG_IDS, TRAVELPAYOUTS_TOKEN/MARKER, ADMIN_PASSWORD, JWT_SECRET
cd backend
py -3.12 -m venv .venv
.venv\Scripts\python -m pip install -e ".[dev]"
.venv\Scripts\alembic upgrade head
.venv\Scripts\python -m bot.main          # бот + фоновая проверка подписок
```

Админка (в другом терминале):

```bash
cd admin && npm install && npm run build   # один раз
cd ../backend && .venv\Scripts\python -m api.main   # http://localhost:8000
```

Разработка админки с горячей перезагрузкой: `cd admin && npm run dev` → http://localhost:5173 (API проксируется на :8000).

Если Telegram доступен только через VPN — бот сам возьмёт системный прокси или `TELEGRAM_PROXY` из `.env`.

## Docker (сервер)

```bash
cp .env.example .env    # заполнить
docker compose up -d --build
```

Поднимаются: `postgres`, `redis`, `migrate` (миграции), `bot`, `api` (админка на порту `API_PORT`, по умолчанию 8000), `prometheus` + `node-exporter`. Проверено: миграции и полный поиск на Postgres.

> На Windows, если в пути к проекту есть кириллица, `docker compose build` падает с ошибкой BuildKit (`x-docker-expose-session-sharedkey … non-printable ASCII`). Соберите образ напрямую и поднимайте без `--build`:
> `docker build -t aviawatch:latest .` → `docker compose up -d`.

> ⚠️ Один токен бота — один запущенный бот. Перед `docker compose up` остановите локального бота, иначе Telegram отдаст ошибку конфликта.

## Проверка

```bash
cd backend
.venv\Scripts\python -m pytest                                   # 92 теста, без сети
.venv\Scripts\python -m sources.check --list
.venv\Scripts\python -m sources.check kupibilet HRG MOW 2026-11-20 --adults 2
```

Тесты парсеров работают на сохранённых реальных ответах сайтов (`tests/fixtures/`), сквозной тест бота (`tests/test_bot_flow.py`) проходит весь путь пользователя через настоящий диспетчер aiogram с подменённым Telegram.

## Структура

```
backend/
  common/      конфиг, БД и модели, метрики, справочник аэропортов, настройки приложения
  sources/     источники (по файлу на сайт), telegram.py — общее для каналов, registry, CLI check
  search/      оркестратор, runner, фильтры, склейка, кэш, история, аналитика, рекомендация,
               составные маршруты (combos), гибкие даты (flexible)
  scheduler/   проверка подписок и правила уведомлений
  bot/         Telegram-бот (aiogram 3)
  api/         API админки (FastAPI)
  migrations/  Alembic
  tests/
admin/         веб-админка (React + TS + Vite + Tailwind + Recharts + React Flow)
infra/         Prometheus
```

### Как добавить источник

1. `backend/sources/<name>.py`: класс-наследник `Source` с `@register`, метод `search(query, ctx)` → список `FlightOffer`. Длинные диапазоны дат — через `focus_days(query, ctx)`.
2. Импорт в `sources/registry.py::_load_builtin`.
3. Сохранить реальный ответ в `tests/fixtures/` и написать тест.
4. `python -m sources.check <name> ...` — живая проверка.

Конфиг источника появится в БД при старте бота/API; дальше — включение, прокси, лимиты и «Тест» в конфигураторе админки.
